# Feature Specification: 零标记自动国际化——构建期自动发现并改写文案（v0.2.0）

**Feature Branch**: `004-zero-markup-i18n`

**Created**: 2026-09-06

**Status**: Complete

**Input**: User description: "不使用 $translate 和 autoTranslate 来包裹需要翻译的内容，实现自动翻译——自动查到需要翻译的文本。选定路线：构建期 AST 扫描 + 自动改写"（完整需求与决策见 `docs/requirements.md` v0.2.0 小节）

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 零标记书写文案，构建期自动翻译 (Priority: P1)

作为接入方开发者，我在 Vue 单文件组件中直接书写中文文案——模板文本节点、模板插值中的字符串、绑定属性（如 `:placeholder`）中的字符串、script 中的字符串字面量——不写任何 `$translate` / `autoTranslate` 包裹；开发构建时这些文案被自动发现、翻译并持久化到翻译文件；运行时切换语言时页面响应式显示对应译文。

**Why this priority**: 这是本库"中文即 Key"理念的自然完成形态——消除逐处包裹的业务代码侵入，是 v0.2.0 的核心价值；没有它，本版本不成立。

**Independent Test**: 在一个不含任何显式翻译调用的 SFC 中书写中文文案并执行开发构建，翻译文件新增对应词条；运行时切换语言，页面显示对应译文且响应式生效。

**Acceptance Scenarios**:

1. **Given** 模板文本节点直接书写中文的 SFC，**When** 开发构建执行，**Then** 该文本被提取、翻译并写入翻译文件，运行时切换语言后显示译文
2. **Given** 模板插值 `{{ '中文' }}` 与绑定属性 `:placeholder="'中文'"`，**When** 构建执行，**Then** 两者均被提取翻译并在运行时随语言切换
3. **Given** script 中 `const label = '中文标签'` 形式的字符串字面量，**When** 构建执行，**Then** 该字面量被改写为查表调用，取值随语言切换响应式更新
4. **Given** 同一文件混合显式 `$translate` 调用与零标记中文文案，**When** 构建执行，**Then** 两者均正常工作、互不干扰，词条按相同哈希键合并不重复
5. **Given** 生产构建产物，**When** 部署后访问页面，**Then** 零标记文案按部署的翻译文件正确显示当前语言译文（与显式写法生产行为一致）

---

### User Story 2 - 误判防护与忽略机制 (Priority: P2)

作为接入方开发者，我的非文案代码（属性访问器、对象属性键、注释等含中文的字符串）不被自动改写、运行语义不被破坏；对个别自动判定不合意的场景，我能用注释级或配置级手段显式排除。

**Why this priority**: 自动扫描的最大风险是把代码当文案改写导致运行时语义破坏——"绝不改坏代码"是自动翻译能被信任的前提，优先级仅次于核心能力本身。

**Independent Test**: 构建含 `obj['中文key']`、含中文对象键、含中文注释、含忽略注释的 SFC，断言产物中这些内容原样保留、对应字符串未产生词条；忽略注释覆盖的字符串不参与翻译。

**Acceptance Scenarios**:

1. **Given** 属性访问器字符串 `obj['中文属性名']`，**When** 构建执行，**Then** 该字符串原样保留，不产生词条、不改写
2. **Given** 对象属性键 `{ '中文键': value }`，**When** 构建执行，**Then** 键名原样保留
3. **Given** script 或模板中的注释包含中文，**When** 构建执行，**Then** 注释内容不被提取
4. **Given** 被忽略注释标记覆盖的字符串，**When** 构建执行，**Then** 该字符串不参与翻译、不被改写
5. **Given** 接入方在插件配置中声明排除规则（文件路径或代码范围），**When** 构建执行，**Then** 匹配范围不参与零标记扫描

---

### User Story 3 - 显式 API 逃生舱共存 (Priority: P3)

作为接入方开发者，升级后现有 `$translate` / `autoTranslate` 写法行为完全不变：带插值参数的复杂场景（`{name}` 占位符 + 动态值）仍用显式 API 表达；同一项目中两种写法自由混用，存量代码无需重写即可升级。

**Why this priority**: 显式 API 是插值场景的可靠表达方式与自动判定失准时的兜底，保证升级是渐进式而非强制迁移；但其行为在本版本中是"保持不变"，非新增能力，优先级低于前两者。

**Independent Test**: 以 v0.0.x 的显式写法用例（既有测试套件）回归构建，零失败、产物行为与升级前一致。

**Acceptance Scenarios**:

1. **Given** 使用显式 `$translate` / `autoTranslate` 的存量代码，**When** 升级后构建，**Then** 行为与升级前完全一致（既有测试零回退）
2. **Given** 需要插值的文案场景，**When** 开发者选择显式 API 表达，**Then** 插值行为（占位符保留、动态值替换、响应式切换）与现行一致
3. **Given** 同一项目混用两种写法，**When** 构建执行，**Then** 无冲突、无重复词条、无双重改写（显式调用点不被零标记扫描二次处理）

### User Story 4 - 文档、演示与版本同步 (Priority: P4)

作为评估与维护本库的使用者和贡献者，我能在双语 README 中看到零标记用法的说明、忽略机制文档与适用边界（如"纯英文源文本不适用"）；演示应用以真实页面展示零标记能力；CHANGELOG 记录 v0.2.0 变更；包版本与插件内置版本一致升至 0.2.0。

**Why this priority**: 文档与版本同步是变更可被发现、可被追溯的保障，属于交付物完整性而非运行时能力，优先级最低。

**Independent Test**: 人工核对双语 README 用法与边界说明、演示页零标记区块、CHANGELOG v0.2.0 条目、包版本与插件内置版本常量两处一致。

**Acceptance Scenarios**:

1. **Given** v0.2.0 完成，**When** 使用者阅读双语 README，**Then** 能看到零标记用法、忽略机制、适用边界（含"纯英文源文本场景不适用"的明示）与显式 API 共存说明
2. **Given** 演示应用，**When** 访问零标记演示区块并切换语言，**Then** 未经任何包裹的中文文案随语言正确切换
3. **Given** 仓库，**When** 查看 CHANGELOG 与版本标识，**Then** v0.2.0 条目存在，包版本与插件内置版本常量一致为 0.2.0

### Edge Cases

- 纯英文 / 不含 CJK 字符的字符串：默认不参与翻译（不在扫描判定范围），行为与"无翻译需求"一致
- 跨字面量的字符串拼接（如 `'共' + n + '条'`）：首版不自动改写、不产生词条，文档明示此类场景改用显式 `autoTranslate(\`共{n}条\`, { n })` 表达（插值能力本就在显式 API 中）
- 独立 `.ts` / `.js` 源文件（如 Pinia store、utils）：首版不在扫描范围，零标记能力仅覆盖 `.vue` 单文件组件（与现有插件管线一致）；此类文件中的文案仍用显式 `autoTranslate` 表达
- 无 `<script>` 块的 SFC：沿用现有注入机制追加脚本块承载查表代码，不产生语法错误
- 运行时插件未安装：改写后的查表调用回退显示原文，不抛错（与现有显式写法回退行为一致）
- 翻译源失败（网络/配置异常）：仅警告并跳过新增文案，构建不中断，已缓存词条继续生效
- 同一文案既有显式调用又有零标记出现：哈希键相同，词条唯一合并，显式调用点不被零标记扫描二次改写
- 开发构建与生产构建的差异行为：零标记改写两种模式均生效——生产产物中零标记文案必须能显示译文；具体机制（注入子集表 vs 保留调用走全局查表）由实施计划决定，spec 只约束行为结果
- 大体量项目构建性能：扫描与改写为构建期一次性成本，不得显著拖慢开发构建（与现有提取同量级）

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 在构建期自动发现 Vue 单文件组件中未经显式 API 包裹的中文文案，覆盖四类位置：模板文本节点、模板插值表达式中的字符串字面量、模板绑定属性中的字符串字面量、script 中的字符串字面量
- **FR-002**: 发现的零标记文案 MUST 进入与显式 API 完全相同的翻译管线——相同的内容哈希键、相同的翻译源优先级（自定义 > LLM > 免费默认）、相同的翻译缓存文件；两种来源的词条 MUST 合且不重复
- **FR-003**: 系统 MUST 将发现的文案改写为运行时查表调用，使语言切换响应式生效；开发构建与生产构建的页面产物中，零标记文案 MUST 均正确显示当前语言译文
- **FR-004**: 文案判定 MUST 以"字符串包含 CJK（中文）字符"为主要启发式；不含 CJK 字符的字符串 MUST NOT 参与零标记翻译
- **FR-005**: 属性访问器字符串（`obj['中文key']`）、对象属性键、注释内容 MUST NOT 被提取或改写；改写 MUST NOT 改变被改写语句之外的任何代码语义
- **FR-006**: 系统 MUST 提供注释级忽略机制——被忽略标记覆盖的字符串不参与提取与改写
- **FR-007**: 系统 MUST 提供配置级排除机制——接入方可声明规则排除指定文件或代码范围不参与零标记扫描
- **FR-008**: 现有显式 API（`$translate` / `autoTranslate`）MUST 保持既有行为完全不变；显式调用点 MUST NOT 被零标记扫描二次处理
- **FR-009**: 翻译失败 MUST 仅警告不中断构建（延续既有 FR-007 约束）；运行时插件未安装时查表调用 MUST 回退原文
- **FR-010**: 零标记扫描 MUST 默认开启且可通过插件配置关闭（升级即生效，体现零接入成本；配置开关保障存量项目可控回退）
- **FR-011**: 面向使用者的文档 MUST 同步更新——双语 README（零标记用法、忽略机制、适用边界、与显式 API 共存说明）、CHANGELOG（v0.2.0 条目）、CLAUDE.md（架构描述）；包版本与插件内置版本 MUST 一致升至 0.2.0
- **FR-012**: 测试 MUST 全部离线运行（stub 网络请求，不调用收费接口）；新增覆盖扫描、改写、忽略机制与边界用例（属性访问器、对象键、注释、无 script 的 SFC、混合写法、生产构建）的单元与集成测试；既有用例零回退

### Key Entities *(include if feature involves data)*

- **零标记文案（Zero-markup Text）**: SFC 源码中未经显式 API 包裹、经 CJK 启发式判定为文案的字符串；与显式文案共享同一词条模型（内容哈希键 → 各语言译文），是本功能新增的词条来源
- **忽略标记（Ignore Marker）**: 源码注释形式的局部排除指令，覆盖其标记的字符串或代码范围；属接入方的判定修正手段
- **扫描配置（Scan Config）**: 插件配置的新增组成部分——零标记扫描开关、配置级排除规则；随插件实例独立生效
- **词条缓存（Translate Cache）**: 既有实体（内容哈希键 → 各语言译文的持久化 JSON），本功能仅新增其来源，结构与命中行为不变

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 演示应用新增零标记演示区块：构建后词条全部落盘，开发与生产产物中切换语言均正确显示译文，与显式写法行为无差异
- **SC-002**: 误判防护 100%：属性访问器、对象属性键、注释在自动化测试中零改写、零词条；正常文案判定无遗漏（给定样例集全覆盖）
- **SC-003**: 既有显式 API 测试套件零回退；全量测试（单元/集成/Use Case/e2e）与类型检查通过
- **SC-004**: 新增能力（扫描、改写、忽略、边界）有完整自动化测试覆盖，全部离线运行
- **SC-005**: 双语 README、CHANGELOG、CLAUDE.md 更新完毕；包版本与插件内置版本一致为 0.2.0
- **SC-006**: 业务代码零标记改造后的接入成本可观测：演示页同一区块的显式写法与零标记写法代码行数对比写入演示说明（预期零标记写法不含任何翻译函数调用）

## Assumptions

- 首版扫描以 `.vue` 单文件组件为对象（与现有插件管线 `transform` 只处理 `.vue` 保持一致），不扩展到独立脚本文件
- 改写复用现有注入与查表机制（开发期子集注入 / 生产期全局查表），具体形态由实施计划决定，不引入新的运行时依赖
- 忽略注释的具体语法（如 `/* autoi18n-ignore */`）由实施计划定夺，spec 只约束"注释级 + 配置级"两级排除能力
- 演示应用继续承担 dogfood 职责：新能力先在演示应用中真实使用并纳入 e2e
- 项目"中文即 Key"定位不变：纯英文源文本场景明确不支持（需求分析阶段已确认，README 需明示该边界）
- 版本号定为 0.2.0（0.1.0 已随 npm 发布工作流占用；新功能按语义化版本属 minor 升级）
- 三个范围决策（扫描范围、拼接处理、默认启停）在 2026-09-06 clarify 提问中用户未即时答复，按推荐默认固化：仅 `.vue`、拼接首版跳过、默认开启；如后续有不同意见按 minor 修订调整
